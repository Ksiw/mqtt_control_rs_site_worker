# site_worker (Cloud Hub & Reverse Proxy for mqtt_control_rs)

Бессерверный сервис на базе **Cloudflare Workers + D1 Database** для объединения распределённых установок `mqtt_control_rs` в защищённую промышленную экосистему с единой точкой входа.

## Что реализовано в каркасе:
1. **База данных Cloudflare D1:**
   - Таблицы пользователей (`users`), сессий (`user_sessions`), организаций (`organizations`), подписок (`subscriptions`), рабочих пространств (`workspaces`), узлов программы (`devices`), дашбордов (`dashboards`), прав доступа (`dashboard_permissions`) и журнала аудита (`audit_logs`).
   - Миграция: `migrations/0001_initial_schema.sql`.
2. **Протокол Heartbeat программы (REST API):**
   - `POST /api/v1/device/heartbeat` — приём регулярных запросов состояния программы (каждые 30 сек).
   - Проверка HMAC и допустимого временного окна; уникальность каждого запроса пока не контролируется.
   - Автоматическая регистрация и обновление дашбордов рабочего пространства в базе данных D1.
3. **Отказоустойчивый шлюз (Reverse Proxy Gateway):**
   - `GET /view/:org_slug/:ws_slug/:dash_id` — единый красивый URL для браузера оператора без раскрытия адреса `trycloudflare.com`.
   - Автоматическое горячее переключение (Failover): направление трафика на узел `primary`, а при сбое — на `standby`.
   - Прозрачное проксирование дуплексных соединений WebSocket (`Upgrade: websocket`).
4. **Фоновый планировщик (Cron Trigger):**
   - Выполняется каждую 1 минуту (`* * * * *`).
   - Автоматически переводит зависшие или отключённые узлы в статус оффлайн (`is_online = 0`).

## Структура Worker

- `src/index.ts` регистрирует маршруты и запускает регламентную очистку.
- `src/core/` содержит общие проверки сессии, права администратора и чтение цен.
- Для закрепления прав супер-администратора за неизменяемым аккаунтом задайте секрет Worker `SUPERADMIN_GOOGLE_ID` со значением `sub` нужного аккаунта Google. Пока секрет не задан, сохраняется прежняя проверка по адресу почты.
- `src/crypto.ts` выпускает ключи устройств и выполняет криптографические операции.
- `src/proxy.ts` выбирает доступный хост и проверяет права; `src/proxy/shared.ts` очищает заголовки и сохраняет cookie хаба при проксировании.
- `src/billing.ts` создаёт счета и отдаёт историю; `src/billing/webhook.ts` обрабатывает уведомления об оплате; `src/billing_application.ts` атомарно применяет подтверждённый платёж.
- `src/pairing.ts` создаёт запросы привязки и отдаёт их состояние; `src/pairing/approval.ts` подтверждает привязку и меняет устройства.
- `src/cabinet_views.ts`, `src/cabinet_modals.ts`, `src/cabinet_scripts.ts` и `src/admin_view.ts` формируют интерфейс; запись в базу остаётся в маршрутах и модулях ядра.

## Лицензия настольного приложения

`POST /api/v1/auth/google` принимает Google ID token, проверяет его у Google и выдаёт
сессию из `user_sessions`. `GET /api/v1/me` принимает эту сессию в заголовке
`Authorization: Bearer <token>` и возвращает подписки организаций владельца,
включая дату окончания. Истёкшие, отменённые и просроченные подписки не дают
платную редакцию. Подтверждение платной подписки подписывается ключом
`LICENSE_SIGNING_KEY` (секрет worker), чтобы приложение могло проверять её без сети.
Программа обновляет статус раз в сутки и доверяет последнему подписанному ответу
до даты окончания оплаченной подписки.
Для настольного клиента разрешён `GOOGLE_DESKTOP_CLIENT_ID`
в `wrangler.toml`; браузерный клиент задаётся `GOOGLE_CLIENT_ID`.

После изменения worker его нужно опубликовать отдельно от приложения.
Перед публикацией этой версии примените миграции D1: `npm run d1:remote`.
Миграция `0008_payment_application.sql` добавляет отметку об учтённом платеже;
без неё обработчик оплат не сможет работать.
Перед публикацией обработчика оплат также требуется `0010_billing_integrity.sql`:
она добавляет защиту параллельных продлений, исходный день оплаты и очередь сверки
спорных платежей. Сначала примените миграции, затем публикуйте Worker.
Миграция `0011_payment_refunds.sql` хранит возвраты по идентификаторам отдельных
попыток оплаты, поэтому возврат одной попытки не закрывает весь счёт.
Миграция `0012_unique_subscription_per_org.sql` обеспечивает одну запись текущих
прав на организацию. Количество счетов и оплат она не ограничивает. Если в D1
уже есть несколько записей подписки для одной организации, сначала требуется
разобрать их вручную: миграция остановится, не удаляя данные.
Спорные платежи доступны супер-администратору через `GET /api/v1/billing/reviews`.

## Комментарии в wiki

Публичные статьи собираются из локальных файлов сайта. Worker не предоставляет API создания или изменения статей. Зарегистрированные пользователи могут читать и оставлять комментарии; удалять комментарий может только его автор.

Чтобы включить комментарии, примените миграцию `0009_wiki_comments.sql` к D1 и опубликуйте Worker:

```bash
npm run d1:remote
npm run deploy
```

## Команды разработчика:

```bash
# Проверка TypeScript и совпадения ресурсов с соседним mqtt_control_rs
npm run check

# Проверки подписи устройств, вебхука, тарифа и HTML
npm test

# Применение миграций базы данных D1 локально
npm run d1:local

# Локальный запуск эмулятора воркера
npm run dev

# Публикация в облако Cloudflare
npm run deploy
```
